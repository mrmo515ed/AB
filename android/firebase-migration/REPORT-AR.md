## 2) ما أُصلح في هذه الجلسة (كود حقيقي)

### أندرويد
1. **ربط السيرفر من داخل التطبيق** — شاشة جديدة: **الإعدادات ← التشخيص ← خادم الذكاء الاصطناعي**:
   - عرض العنوان الحالي، إدخال عنوان جديد، **اختبار الاتصال** (`GET /api/health`)، واستعادة العنوان المدمج.
   - يُحفظ على الجهاز (DataStore) ويُستخدم فورًا — **لا حاجة لإعادة بناء الـ APK لتغيير السيرفر**.
2. **حذف الحساب كان يفشل** إذا مضى أكثر من 5 دقائق على آخر دخول → الآن يُعيد تسجيل الدخول بجوجل تلقائيًا ثم يُكمل الحذف.
3. **إصلاح خطر انهيار** في الشاشة الرئيسية (`state.error!!`).
4. **حالة الوكيل الذكي أصبحت حيّة** (تتحدث فورًا عند تغيير السيرفر).
5. **تنظيف**: إزالة مفتاح `HAS_GOOGLE_SERVICES_JSON` الميت.
6. **شبكة**: في نسخ التطوير فقط، يُسمح بـ http للخوادم المحلية (`10.0.2.2` / `localhost`) لتجربة سيرفرك؛ نسخ الإصدار تبقى https فقط.
7. **توكن API اختياري** (`ANIMEBLACK_APITOKEN`) يرسله التطبيق في ترويسة `x-ab-token`.

### السيرفر (Node)
8. `/api/gemini/search-agent`: **حد معدّل 20 طلب/دقيقة لكل IP** + حد لطول الطلب + **توكن اختياري** (`ANIMEBLACK_AGENT_TOKEN`).
9. `/api/admin/metrics`: **توكن اختياري** (`ANIMEBLACK_ADMIN_TOKEN`) + حد معدّل.
   - كل هذا **اختياري**: إن لم تضبط المتغيرات لا يتغير شيء (الصفحة والتطبيق يعملان كالمعتاد).

### الفهارس والقواعد
10. `functions/src/index.ts`: الافتراضي لقاعدة الدوال أصبح `(default)` (المشروع الجديد) مع إمكانية التجاوز لسيرفر الويب القديم.
11. قواعد Firestore/Storage جاهزة للنشر في `android/firebase-migration/` (لم تُنشر — لا وصول لي إلى Console).

## 6) بعد تثبيت التطبيق — كيف تربط سيرفرك؟

1. افتح التطبيق ← **الإعدادات** ← قسم **التشخيص** ← **خادم الذكاء الاصطناعي**.
2. أدخل عنوان سيرفرك (يبدأ بـ `https://`) ← **حفظ** ← **اختبار الاتصال** (يجب أن يظهر «الخادم متاح ✔»).
3. من هذه اللحظة يعمل **وكيل البحث الذكي** (Anime ← أيقونة ✨) عبر سيرفرك.
   - إن لم تُدخل عنوانًا: الوكيل يعرض «غير مُهيّأ» (ولا يوجد زر معطّل يخدعك).
   - في نسخ التطوير فقط يمكن استخدام `http://10.0.2.2:3000` (محاكي) أو `http://localhost:3000`.
4. إن أردت أن يكون العنوان **مدمجًا في الـ APK** منذ البداية: أرسل لي العنوان وسأضيفه كقيمة افتراضية عبر `local.properties`/وسم البناء، أو أضف أنت السر `ANIMEBLACK_APIBASEURL` في المستودع.

> **تنبيه أمني (موصى به):** عند إتاحة السيرفر على الإنترنت اضبط على الخادم:
> `ANIMEBLACK_AGENT_TOKEN=<توكن سري>` ثم ضع نفس التوكن في التطبيق عبر السر `ANIMEBLACK_APITOKEN` عند البناء — وإلا فسيكون الوكيل مفتوحًا للعموم مع استهلاك مفتاح Gemini. (حد المعدّل فعّال دائمًا بدون أي إعداد.)

## 7) ما لا أستطيع فعله (بصراحة كاملة)

| البند | السبب |
| --- | --- |
| إنشاء Firestore / تفعيل المزوّدين / إضافة البصمات | لا أملك وصولًا إلى Firebase Console (ولا gcloud). هذه الخطوات عليك. |
| نشر القواعد والفهارس والدوال | تحتاج حسابًا مُصدَّقًا (Firebase CLI). الملفات جاهزة للنسخ/النشر. |
| نسخة موقّعة بمفتاح إصدار | لا يوجد مفتاح إصدار في المشروع. الـ APK الحالي موقّع بمفتاح التطوير (مناسب للتجربة، وليس للنشر على Google Play). |
| تفعيل Storage | غير مصرّح بالفاتورة (بقرارك). |
| Docker / استضافة | لا مزوّد سحابي مربوط بحسابك. |

## 9) المخاطر المتبقية

1. **Google Sign-In**: لن يعمل قبل الخطوة 4 (البصمة). الرسالة في التطبيق توضح ذلك بدقة.
2. **Firestore**: كل القراءات/الكتابات ستُرفض قبل الخطوتين 1 و2 (production mode + القواعد).
3. **الدخول السريع (Anonymous)**: معطّل حاليًا → فعّله (الخطوة 3) أو استخدم جوجل/البريد.
4. **الوسائط (Storage)**: رفع الصور/الفيديو سيفشل ويُحفظ في قائمة إعادة المحاولة (الإعدادات ← تشخيص المزامنة).
5. **الدوال**: المكافأة اليومية/تحويل العملات/إشعارات الدردشة تحتاج نشر الدوال (Blaze).
6. **`users` قابلة للقراءة العامة** (بتصميم الموقع) وتشمل البريد — خطر موثّق، يُنصح بنقل البريد لمستند خاص لاحقًا.
7. **لا مفتاح إصدار ولا `versionCode` متقدم** — مطلوب قبل النشر على Google Play.
